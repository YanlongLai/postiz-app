# Bounded integration and verification

## Sequence

A. Resolve upstream merge conflicts by behavior: reconcile public API additions
with authenticated receipt routes; retain old workflow exports and version new
workflow changes; preserve LinkedIn analytics fallbacks. Compare automatic merge
of Prisma schema and activities as carefully as conflicted files.

B. Rebuild from the updated locked dependencies, not the previous overlay base
whose byte-equality guard is intentionally incompatible. Keep no schema reset or
db-push at ordinary startup; apply additive reviewed migration separately.

C. Resolve currently running n8n digest and image metadata; use a canonical pin
shared by Deployment/import Job. Avoid a floating stable mirror or tag-only fix.

D. Investigate existing bundle API before changing cold startup. Generate one
main bundle for the exact image and version; provider workers activity-only.
Test missing/mismatched bundle and old Temporal history compatibility; measure
startup before/after on isolated runtime. Do not widen timeouts as optimization.

E. Do not let native Job TTL bypass archival. Newly created schema/import Jobs
have no automatic TTL; explicitly allowlisted legacy TTL must be paused and
observed before archival. Terminal ReplicaSet pods use the same bounded
evidence-preserving maintenance entry point. Default retention must
keep original failure records and protect active work; tests cover scope/age/owner.

F. Reuse existing gateway verifier and encrypted restore staging. Disposable DB
has isolated credentials/network, no service routing or Postiz processes; import
only approved backup components and verify schema/counts/capabilities. Durable
proof contains no production row content or secret. Cleanup exact owned target.

## Release safety

Freeze merged Postiz image digest, Marketing manifest and Meta helper identities.
Verify dependency closure and official staged Postiz readiness including main and
provider pollers, V113 capability and former workflow exports. Don't start a
second publisher during canary. Backup before schema update; preserve full old
workflow support while existing executions remain. Do not deploy unrelated apps.

## Review delegation

Read-only bounded analysis may be delegated: boundaries clear, success criteria
file/line grounded, reversible, no secret or external writes, no product decision.
Independent assurance must be a different reviewer, not a producer self-claim.
